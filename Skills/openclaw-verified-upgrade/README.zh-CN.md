围绕官方持久升级事务、完整恢复材料和实际运行证据的 OpenClaw 安全升级技能。

## 当前流程

解析精确目标，检查安装驱动和目标版本合同，建立恢复源清单并验证备份覆盖，选择唯一生命周期所有者，执行已批准阶段，跟进原事务直至运行验收与完整观察窗口通过。

标准升级范围延续既有授权，不重复设置确认门槛；降级、权限扩大、未接受的高影响迁移、凭证、服务重建、破坏性清理和不安全恢复仍按实际范围授权。一次升级不等于开启自动更新或发布技能。

优先使用官方持久升级器。旧驱动本身无法完成某项已记录流程时，可以在精确目标、独立恢复包、运行时兼容和维护计划均已核实的前提下，使用官方支持的外部包管理器流程。不能把它当作未知事务的盲目重试，也不自动安装自建协调器。

核心包替换与同版本官方插件维护分别记账；私有 Node 准备可以是另一个已批准阶段。稳定性按用户约定的完整窗口验证，不能裁掉早期失败。清理按已授权保留策略，只删除本轮已证明冗余的对象。

## 完成证据

- CLI、安装包与实际 Gateway 的版本、路径、运行时相符。
- 插件符合各自合同，关键插件实际加载；不按版本数字粗暴统一独立版本插件。
- 配置、所需数据库、SQLite 定时任务语义、Agent 路由与关键工作流对照基线通过。
- 在授权范围内测试实际主模型路径；连接状态不等于外部消息投递已验证。
- 完整观察窗口通过，恢复材料独立可用。
- 若已授权清理，执行后再检查普通 CLI 和网关。

单次 exit 0、端口监听、ready 日志或 CLI 版本不能单独证明完成。缺少关键验证时报告“已安装，验收未完成”；只降包不能撤销数据库迁移。

## 本地维护与分发

维护一份经审阅的源码，再部署已验证技能包并核对实际解析路径。共享目录、Workshop 和插件副本可能不同；不要直接编辑生成缓存作为长期源。

公开发布从已核实的 GitHub 提交构建，分别核对平台公开版本与审核状态，不把上传回执当成已公开或审核通过。技能行为通过离线场景审阅，不用真实主机升级或重启代替测试。
