# PPTSmith 2.1 RC1 Acceptance Report

## Outcome

PPTSmith 2.1 RC1 is accepted for Standard production on the verified macOS
environment with LibreOffice 26.2.4.2 available as the real renderer.

This claim is intentionally narrower than universal Premium readiness.

## Release gates

- Public unit and schema suite: 223 passed.
- Public integration suite: 26 passed.
- Python modules: compileall passed.
- Latin America consulting-report regression: 12/12 slides rendered.
- Structural QA: 0 fatal, 0 error, 0 warning.
- Trusted delivery status: `verified`.
- Editable core ratio: 1.0.
- Render success ratio: 1.0.
- Whole-slide raster count: 0.
- Native evidence: one chart, one table, nine connectors, editable text and
  diagram labels.

## RC1 fixes

- Deduplicate title, judgment, and message text in both generation and editable
  coverage metrics.
- Omit empty layered-architecture boundary labels.
- Distinguish empty auto-shapes from true empty text boxes.
- Apply the footnote minimum to semantic footers and source notes.
- Treat severe estimated overflow as a hard error while avoiding single-line
  false positives.
- Detect hard text/background contrast failures.
- Detect unsafe text in arrow and chevron notch/head zones.
- Clear render outputs before retries and resumed runs.
- Promote a successful Standard render PDF into the delivery package.
- Add presentation-scale covers, full-canvas single charts and tables,
  editable metric walls, and native source footers/page numbers.
- Exempt semantically named metric-wall text from generic fragmentation noise.

## Regression evidence

The known McKinsey S02 and S10 defects are now represented by blocking rules:
severe overflow and unsafe chevron insets. The Latin America report was then
regenerated through the generic pipeline rather than the earlier custom
reconstruction script. The accepted final package completed Build, Inspect,
Render, Verify, Prepare Delivery, and Package Delivery without manual geometry
repair.

The complete ten-slide McKinsey regression was subsequently rerun against RC1.
The previous visual candidate is now rejected with 24 errors and 49 warnings:
S02 includes a severe overflow estimate of 2.5001, while S10 includes ten unsafe
chevron-inset errors. The RC1 generic rebuild rendered 10/10 slides with zero QA
issues, zero render warnings, zero render errors, and no whole-slide raster.

Manual contact-sheet review also exposed generic layout weaknesses that the
structural gate did not report: a single card used only a small corner of the
canvas, low-row tables were stretched to the full table height, and a single
process sat too high. RC1 now expands single cards, vertically balances a lone
process, and compacts two- or three-row tables with a 13pt minimum. The source
PPT IR remains intentionally disclosed as under-specified for showcase use.

## Honest limitations

- The generic builder now produces a clean consulting baseline, not a bespoke
  agency-designed deck.
- Rich source-specific visuals still depend on sufficiently semantic PPT IR;
  unlabeled numeric arrays cannot become meaningful executive graphics by
  layout logic alone.
- Premium final readiness remains conditional on the target renderer,
  readback environment, rubric score, and disclosed fallbacks.

## Hero Showcase evidence

The release candidate was also exercised on the 290-page World Economic Forum
*Future of Jobs Report 2025*. A 12-slide Chinese executive showcase was built
with 460 native shapes, 53 native connectors, 2,727 native text characters,
zero media files, and zero whole-slide rasterization.

The first true render was not released even though the deck opened correctly.
Manual inspection found a job-loss label outside its colored container,
connectors crossing text on the macro-forces page, and a closing loop whose
connectors crossed stage labels. Structural inspection detected only part of
that set. After repair and a second review loop, the final package rendered
12/12 slides and passed structural inspection with zero errors and zero
warnings. Internal rubric score: 17/18.

This showcase demonstrates the upper bound of the v2.1 visual system under a
high-fidelity native build. It does not change the release boundary above:
generic Standard readiness is verified, while Premium quality remains
run-specific and requires the complete render/readback/revision gate.
